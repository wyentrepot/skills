# 格式规范

处理文件组织、头文件、注释、缩进、空格、括号、换行和代码长度时读取本模块。

## 文件规则（9 条）

- C 头文件用 `.h`，源文件用 `.c`；其他语言文件沿用原规范约定。
- C 头文件和源文件名字一致（含大小写），只有扩展名不同。
- 文件名禁止仅通过大小写区分。
- 每个模块的头文件与源文件职责应清晰对应。
- 引用系统库头文件用 `<>`，其他头文件用 `""`。
- 头文件引用顺序：系统库 → 第三方 → 自有。
- 只包含需要的头文件，移除不再需要的。
- 头文件必须有防止多次包含的保护（如 `#ifndef`）。
- 头文件不要引用不必要的其他头文件；优先在源文件中引用。

## 注释规则（7 条）

- 单行注释可用 `//` 或 `/* ... */`，多行注释用 `/* ... */`；具体形式与当前文件保持一致。
- 文件必须以注释开始，包含版权、作者、简述等信息。
- 作为接口的函数必须提供功能、参数、返回值注释。
- 常量、全局变量、静态变量定义时必须带注释。
- 注释要尽量靠近被解释的代码。
- 注释掉的源代码必须删除；确需保留时使用条件编译。
- 注释尽量使用英文 **[建议]**。

## 格式规则（16 条）

- 每行代码不超过 80 字符，最多 100 字符；过长时在逗号或操作符处拆行并对齐。
- 每个函数代码行数不超过 200 行。
- 每个文件代码行数不超过 2000 行，自动生成代码和资源文件除外。
- 每行只能写 1 条语句。
- 缩进使用 4 个空格。
- Tab 按 4 个空格处理，并与当前文件保持一致。
- `if`、`else`、`while` 等语句块内代码缩进 4 个空格。
- 行尾不要遗留空格。
- 指针声明中的 `*` 与类型连在一起，后面空格接变量；已有模块风格不一致时遵循最小 diff。
- 一元操作符（`&`、`*`、`++`、`--`）与操作数之间不留空格。
- 逗号和分号后面留 1 个空格。
- 二元操作符前后留空格；`->`、`.`、`()`、`[]` 前后不留空格。
- 函数名与左括号之间不留空格；语句小括号外留空格，括号内不留空格。
- 大括号形式与当前文件保持一致。
- 第一个函数参数与函数同行；空间不足时每个参数单独成行并对齐。
- 函数代码较多时可划分多个代码区域并添加说明注释 **[建议]**。
