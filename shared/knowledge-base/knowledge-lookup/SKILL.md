# 知识库查阅（渐进式加载）

## 核心原则

1. **先查库，再回答**。本库（121 个 md）是国网/南网协议与业务的一手蒸馏资料。凡协议帧字段、数据单元标识、状态机参数、省份扩展细节，一律查库后回答。训练记忆对常见项（如 645 起始符 68H）也许碰巧正确，但对冷门项（省扩展 DA 映射、CCO 轮次参数）必然含糊或编造。
2. **探测优先，按需加载**：第一步永远是 glob/grep 探测（几十 token），命中即读卡内小节；总索引整读只留给概览题；vault-map 同义词表只作兜底。禁止默认整读总索引/vault-map、禁止整读 40KB 大卡、禁止把整库塞进上下文。
3. **输出契约**：每个结论必须带「文件路径 + 小节标题 + 原文片段(3~8 行)」。

## 库路径与地图

- 库路径：`/01-workfile-ai/04-obsidian/obsidian`（其他环境按实际挂载路径替换）
- **兜底数据 `_meta/vault-map.md`**（随库 git 管理，与 knowledge-manage 共享）：领域同义词表、分诊规则、注意点。**探测全 miss 才查它，且只 grep 相应表段，禁止整读**
- 快速导航：`总索引.md`（`tools/rebuild_index.py` 自动生成的卡名+摘要，basename 短链可直接用）、`00_总述.md`（覆盖范围）、`07_总结.md`（协议分层关系）、`CCO实现逻辑/00-总览.md`（代码落地索引）、`CCO实现逻辑/13-文档与代码差异记录.md`（差异先看它）
- 经验沉淀区：库根 `经验索引.md`（查库前先扫一眼，查完追加）

## 流程

### L0 探测（默认不读索引）
1. **第一步永远是 bash 探测**，不读任何整文件：
   ```bash
   find . -name "*<关键词>*.md" -not -path "*template*" -not -path "*.obsidian*"   # basename 命中
   grep -n "<关键词>" 总索引.md                                                     # 未命中→索引只取命中行
   ```
2. basename 命中 ≥1 张卡 → 直接进 L2，**总索引一个字节不读**
3. 只有两种情况允许读索引：①概览题（"库里有什么/覆盖哪些协议"）；②两轮探测全 miss。且按层读段不整读：
   `sed -n '/## 协议层/,/^## /p' 总索引.md`（业务层/南网/CCO 同理，各段仅 1~2KB）
4. 涉及 CCO 实现时再读 `CCO实现逻辑/00-总览.md`；发现索引与库不符 → 跑 `python3 tools/rebuild_index.py --check` 诊断

### 范围锁定（单层会话）
- 用户声明"只看业务/只查帧格式"，或问题明显单层 → **锁定该层**：探测范围、索引段、L2 全部只在该层进行
- 锁定层查无结果 → 解锁扩到全库，仅此一次；用户未声明且问题跨层 → 默认不锁定（防漏答）

### L1 同义词兜底（探测全 miss 才启用）
1. 原始关键词（含口语变体）glob、索引 grep、全文 grep 全 miss → 才查 `_meta/vault-map.md`
2. 只 grep 相应表段：`grep -B2 -A3 "<领域词>" _meta/vault-map.md`
3. 拿到同义词/目标卡号 → 回到 L0 探测重试
4. 分诊（决定优先看哪层）：帧格式/字段/校验 → `协议层/`（南网→`南网/协议层/`）；业务/方案/流程 → `业务层/`、`05_省份协议/`；代码落地/调用链/状态机 → `CCO实现逻辑/`；差异 → `CCO实现逻辑/13-文档与代码差异记录.md`

### L2 定位 + 片段
1. 标准读法：`grep -n "<关键词>" <命中卡>` 拿行号 → 先看大卡顶部「本卡导航」→ 只读该 `##` 小节（Read offset/limit 或 sed，止于下一标题），引用 3~8 行原文
2. 多命中按问题类型排序（帧→协议层、业务→业务层、代码→CCO），给 top 2~3，说明排除其余的理由
3. 歧义（同一关键词协议层/代码层两处都有）→ 分开标注出处，不合并
4. 卡内数据自相矛盾或与原文不一致 → **诚实标注**（参考 `CCO实现逻辑/13`），需要字节级细节时指出原文在 ima 知识库（卡 `source` 双链），不强行圆场

## 输出契约（每个答案必填）

```
【位置】<相对路径> / ## <小节标题>
【片段】<3~8 行原文引用>
【来源】文档（蒸馏卡） | 代码（template/文件:行号） | 经验/推测 —— 必须区分
```

- 找不到就明说「库内无此内容」，禁止用训练记忆补
- 给「用户问题的直接答案 + 出处」，不空泛复述文档

## 经验沉淀（每次查询后）

- 有非显然发现（新同义词、跨卡关联、踩坑、差异、省差异、检索技巧）→ 向库根 `经验索引.md` 追加一行：
  `- YYYY-MM-DD [关键词]：一句话经验（位置）`
- **追加前先看条目数**：满 20 条或跨月，先按文件头部规则把早期条目移入 `经验索引-归档.md`，再追加
- 已有条目不重复；一句话，不写长文；不记录显然内容

## 常见错误（Red Flags）

| 错误 | 修正 |
| --- | --- |
| 凭记忆答帧字段/状态机参数（尤其省扩展、CCO 参数） | 查库；记忆对冷门项必错 |
| 会话里根本没意识到有库可查 | 本技能存在即触发；凡协议问题先想库 |
| 总索引与库不符仍硬查 | 跑 `tools/rebuild_index.py --check` / `build` 诊断重建 |
| 整读 40KB 卡文件 | 先 grep 定位小节，只读该小节 |
| 默认整读总索引 / 整读 vault-map | 先探测；概览题按层读段；同义词表只 grep 表段 |
| 用户明确单层范围仍全库乱扫 | 范围锁定，锁定层 miss 才解锁一次 |
| 只给结论不给位置+片段 | 输出契约必填 |
| 卡内矛盾强行圆场 | 诚实标注，指原文附录 |
| 查完不沉淀经验 | 追加 `经验索引.md` |
