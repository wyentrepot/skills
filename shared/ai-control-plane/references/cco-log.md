# CCO 模块日志 — 帧特征速查（发送侧真相）

> CCO 固件运行日志 = **发送侧真相**：判定「真没发」还是「发了没抓到」靠它。
> 位置：`.build_plain/data/logs/模块/cco/*.log`（开发树 `data/logs/模块/cco/`）。
> 实战案例见 `使用经验/安徽分钟采集漏点排查.md`。

## 行格式

```
[20260831-19:05:03:581] [RX] 683100c300004000007306201c012101001412230200001931082612006821010014122368910633343435685660168616
```

- `[yyyyMMdd-HH:MM:SS:mmm]` 帧时间戳；`[RX]` 表示该行为日志读取方向（CCO 日志口回读固件输出，非帧方向）。
- 帧 hex 直接出现在行尾，可整段 grep。

## 三类帧特征

| 帧 | 识别正则（对整行 grep -a 小写化后） | 含义 / 方向 |
| --- | --- | --- |
| **06F230 采集上报** | `06201c01`（或 `683300c3`） | CCO → 集中器，被侦听台 `minute_reports` 统计 |
| **11E4 主动上报** | `11e4` | 另一主动上报通道，每周期稳定，冻结=上报−2 分钟 |
| **11E3 补采指令** | `11e3`（⚠ 见下） | CCO 下发补采（弱信号节点靠它补报） |

```bash
grep -aiE "06201c01" .build_plain/data/logs/模块/cco/*.log   # 06F230
grep -ai  "11e4"     .build_plain/data/logs/模块/cco/*.log   # 11E4
grep -aiE "(^|[^0-9a-f])11e3" .build_plain/data/logs/模块/cco/*.log  # 11E3，锚定词边界
```

> **11e3 误报坑**：`11e3` 会作为子串出现在其他 hex 里（如 `b11e3472`）。用词边界锚定，
> 或先看行首 `[timestamp] [RX]` 后是否是独立帧（真实 11E3 帧整行以 `11e3` 开头）。

### 真实样本（20260831 CCO 日志）

```
06F230: [20260831-19:05:03:581] [RX] 683100c300004000007306201c012101001412230200001931082612006821010014122368910633343435685660168616
11E4:   [20260831-19:05:01:843] [RX] 11e400000132080000002400012101001412230102000019310826011200682101001412236891063334343568566016
```

## 冻结字段解析

- **11E4**：帧内 `0102 00XX` 的 `00XX` = **冻结分钟**（如 `01020020` → 冻结 20 分）；冻结时刻 ≈ 上报时刻 − 2 分钟。
- **06F230**：`0200 44/46/48...` 每周期 +2 = **周期序号**（如 44→46→48…）；
  `120109261400` 是**恒定的帧生成时间戳**，别误当冻结时刻。

## 双通道概念（务必分开）

| 通道 | 特征 | 行为 | 谁统计 |
| --- | --- | --- | --- |
| 11E4 主动上报 | `11e4 00000132xx ... 0001 <STA> 0102 00XX 1401092601XX00` | 每 2 分钟稳定，冻结=上报−2 分钟 | 不走 minute_reports |
| 06F230 采集上报 | `68 33 00 c3 ... 06 20 1c 01 <STA> 0200 ...` | 偶发缺帧 | **被 `minute_reports` 统计** |

两条通道行为不同：查「分钟采集缺报」只看 06F230 通道，别拿 11E4 的稳定当 06F230 也不缺。

## 链路在线判定

先确认采集链路在线再判缺报（见 `offline-analysis.md` 第 0 节）：

```bash
grep -aE "串口会话打开|串口会话关闭" .build_plain/data/logs/模块/cco/*.log
```

时段内无任何帧且前后有「关闭/打开」事件 → 链路断线，不是漏。

## 交叉验证结论速记

1. 目标 STA 在 CCO 日志**有** 06F230 → CCO 发了；再查侦听台索引有无该帧，**无 = 接收侧丢帧（真缺）**。
2. CCO **无** 06F230 但有 11e3 补采 → 弱信号节点靠补采才上报（发送侧慢）。
3. CCO **无** 06F230 且无补采、链路在线 → 发送侧未发出，排查集中器/任务配置。
