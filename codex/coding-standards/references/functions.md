# 函数与代码规范

修改函数实现、变量、语句、宏、控制流、共享数据或返回值时读取本模块。

## 通用规则

- 违规必须标记，注释以 `Break rules` 开头。
- 复用遗留代码时，违规标记以 `Legacy Codes` 开头。
- 第三方代码违规标记为 `3rd Party Codes`，且不要修改。
- C 函数实现不要放在头文件中。
- 能使用工程已有库函数时，不自行重复实现。
- 少用宏定义，优先使用常量、枚举或普通函数 **[建议]**。
- 优化顺序：先保证正确，再测量效率，再优化；每次优化后必须测试。
- 优先使用编译系统已有优化选项。
- 代码标识符使用英文字符，字符串内容除外。

## 变量规则

- 所有变量、指针和数组在使用前必须明确赋值。
- 枚举的每个成员必须明确赋值。
- 头文件不要初始化变量，应在源文件中初始化 **[建议]**。
- 少用全局变量，多用局部变量 **[建议]**。
- 文件外不使用的全局变量声明为 `static`。
- 常量全部大写，多单词用下划线连接。

## 语句规则

- 使用常量或枚举代替数字，0 除外。
- 数组和内存分配尽量使用常量代替魔数 **[建议]**。
- 禁止对常量进行无意义的类型转换。
- `if`、`while` 等语句块必须使用 `{}` 明确作用域。
- 计算逻辑复杂时使用小括号明确优先级。
- 小括号嵌套不超过 5 层，超过时拆分表达式。
- `++`、`--` 不要与其他操作符混用在同一语句中。
- 注意递增递减的前后置差异以及 `&&`、`||` 的短路特性 **[建议]**。
- `switch` 必须有 `default` 分支。
- `case`、`default` 必须有 `break` 或 `return`；有意贯穿时注释 `fall through`。
- 空指针使用 `NULL`，不要用 0 表示空指针。
- 不要将指针强制转为整型；确需转换时使用工程明确提供且能容纳指针的类型，并说明编译器依赖。
- 避免多级指针；可以使用结构体表达的数据关系不要使用指针的指针。
- 操作数组下标前必须检测边界。
- 长整型常量后缀使用大写 `L`。
- 使用 `typedef` 定义函数指针 **[建议]**。
- 删除死代码。

## 函数规则

- 函数参数类型尽量保持一致 **[建议]**。
- 参数顺序：先输入参数，后输出参数。
- 输入缓冲区和结构体指针在不修改时使用 `const`。
- 输出参数不得错误地声明为只读。
- 复杂数据结构使用指针传递，避免大对象值复制。
- 对外接口和全局函数参数不超过 5 个；超过时拆分或封装。
- 函数内嵌套不超过 5 层；超过时重构。
- 文件内部函数声明为 `static`。
- 少用 `goto`，优先使用 `return`、`break`、`continue`；统一清理出口除外 **[建议]**。
- 禁止递归调用，使用递推算法替代。
- 函数式宏的每个参数及整个表达式必须加括号。
- 少用全局数据或共享数据 **[建议]**。
- 操作共享数据时使用项目已有同步机制保护。
- 临界区尽量只使用 1 把锁，代码保持短小。
- 可重入函数禁止使用可变的全局或静态数据。
- 必须检查并处理函数返回的错误信息。
