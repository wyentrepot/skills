# 异常与资源规范

涉及错误返回、异常状态、指针、动态内存、句柄、锁、提前返回或清理路径时必须读取本模块。

## 8.1 异常处理策略（建议）

- 尽量避免或控制崩溃。
- 必要时进入安全降级状态。
- 使用工程已有的冗余防护。
- 记录足以定位问题的错误上下文。
- 通过返回码、状态码和错误处理分支处理运行错误。

## 8.2 不要忽略异常或错误（强制执行）

- 必须检查返回码、错误标志、空指针和异常状态。
- 禁止静默吞掉错误或隐藏失败状态。

## 8.3 对异常或错误进行处理（强制执行）

- 仅记录日志不等于完成处理。
- 按场景向调用者返回错误、回滚、重试、降级或进入安全状态。

## 8.4 异常处理需要正确释放资源（强制执行）

- 错误路径必须释放所有已成功获取的动态内存、文件句柄、套接字、锁和其他系统资源。
- 释放顺序与获取顺序相反。
- 任何提前返回或跳转都不得绕过清理。
- 使用统一清理出口或等效机制。
- 部分初始化失败时，也必须释放此前已经获取的资源。

## 8.5 避免指针引发的异常（强制执行）

- 指针定义时必须初始化；无有效目标时使用 `NULL`。
- 解引用、参与内存访问或传入要求非空的接口前必须判空。
- 释放资源后立即将对应指针置为 `NULL`。
- 明确指针所有权，避免悬空指针、重复释放和释放后使用。

## 8.6 嵌入式系统中的异常防护（建议）

- 按系统能力采用看门狗、栈保护、Flash 校验和及受控的异常中断处理。
- 异常中断会增加定位难度，只在必要时使用。
