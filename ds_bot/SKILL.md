# DS Bot 团队治理

管理一台 DSH 上的 Bot 团队：**岗位怎么定、Bot 怎么建、项目怎么加载、记忆怎么不乱、怎么体检。**

> 依据是 `ds-bot` 插件 v0.1.4 的**源码检查**（`src/host/store.js`、`roster.js`、`prompt.js`、`memory.js`）与一次真实团队体检记录。
> 文中出现的 `<项目根>`、`<DSH_HOME>`、`<项目名>`、`<网关A>/<模型A>` 等是**占位符**，不是规则的一部分。

## 什么时候用

- 要**新建 / 改名 / 换模型 / 改 instructions** 之前 → 读 `02-新Bot创建规范-v0.1.md`，逐项过检查清单。
- 要**给 Bot 写 instructions** 时 → 用五段模板（身份 / 项目加载协议 / 职责 / 边界 / 汇报 + 团队硬约束）。
- Bot 记忆出现**串味、归属错误、团队记忆被项目事实污染**时 → 读 `06-记忆治理.md`。
- 做**团队合规体检 / 审计**时 → 跑 `scripts/audit-bots.js`，对照 `04-Bot合规体检-2026-10-13.md`。

## 核心结论（TL;DR）

1. **Bot 是常驻的"人"，不是任务执行器。** 每个 Bot 是一个 dsh Session，有自己的记忆和自己的工作目录；一次性的活走 subagent，不占编制。
2. **岗位＝公司级（跨项目复用），项目＝按需加载。** 岗位卡只写职责与规则；项目事实（根目录、阶段、路径、验收门）写在项目的 `PROJECT-CARD.md` 里，派工时指明项目根目录后由成员加载。
3. **插件里没有"项目"这个对象。** 团队状态只有 `bots / rooms / exchanges / memory(bot+team) / 权限`；全团队共用一个 workspace；项目知识只能靠**记忆 topic** 与**项目文件**承载，靠命名纪律而不是机制。
4. **身份段要字节稳定。** 插件让每个 Bot 的身份提示只依赖它自己的记录，以命中 provider 的 prompt cache；**把项目事实写进 `instructions` 既会腐烂，又会让前缀缓存整体失效**。
5. **记忆只有两层作用域**：每个 Bot 私有的一份 + 全队共享的一份；团队记忆只有 Main Bot 与群管理员能写。上限是硬的：一条 ≤300 字符、`MEMORY.md` ≤4000、topic ≤16000、一个作用域 ≤40 个 topic。
6. **体检要用权威数据，不用印象。** 团队状态读 `<DSH_HOME>/bot/state.json`，记忆读 `<DSH_HOME>/bot/memory/`。

## 八条规则（可检查）

1. 岗位不绑项目——岗位卡零项目事实。
2. 项目事实只进文件（`PROJECT-CARD.md` + 项目自身文档）。
3. 改 `instructions` 视为破坏缓存的操作，须说明影响。
4. 一文件一主，写权以项目档案卡白名单为准。
5. 只追加、不覆盖；**共享文本（群公告、团队文档）先读原文再改，禁止凭记忆整段重写**。
6. 结论标注证据强度；性能数字复测或标注"单次观测"。
7. 一次性的活不建编制：**重复 ≥3 次 / 需独立记忆 / 需独立写权**，三条满足其一才建常驻 Bot。
8. 权限红线：人工审批是唯一闸门；研究角色、聊天入口、模型网关都无模拟执行权限；建人/改名/换模型只有 Main Bot 能做。

## 脚本

```bash
# 团队合规体检（默认读 $DSH_HOME 或 ~/.dsh；DSH_HOME 未设时用 <home>/bot）
node scripts/audit-bots.js
node scripts/audit-bots.js --home "C:/Users/<you>/.dsh" --json audit.json

# 上下文治理落地体检（只读）：每群 admin 是否 = Chief、群 work_dir 是否指向项目目录、
# 每群 admin = Chief；Chief 岗位卡五段与"群内主持派工 / 最终产物验收签发 / 不下场实现"；
# 技术负责人岗四要素升级与"不代签"
node scripts/check-governance.mjs
```

检查项：Bot 数量与角色、`role`/`name` 长度、`instructions` 的五段完整性、项目事实泄漏（绝对路径、项目目录名、数据源/编排器专名、验收编号等）、模型分布、群成员与管理员、记忆目录与 topic 落位。
**退出码 1 表示存在不合规项**（Main Bot 允许没有自定义 instructions），可直接用于 CI 或定时体检。
