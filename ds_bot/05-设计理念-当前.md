# 05 · Bot 团队设计理念（当前版本）

状态：已生效（2026-10-13）· 主责：Chief · 依据：`01-设计意图-源自ds-bot作者.md`、`02-新Bot创建规范-v0.1.md`、`04-Bot合规体检-2026-10-13.md`

---

## 一句话

**把人当人，把项目当文件：岗位公司级、项目按需加载、任务走派工单、权限收在 Main Bot 手里。**

---

## 一、四个层次

| 层 | 是什么 | 载体 | 谁维护 |
| --- | --- | --- | --- |
| **人（岗位）** | 常驻、跨项目复用的角色 | Bot 的 `instructions`（公司级五段卡） | Chief |
| **项目** | 按需加载的项目事实 | 项目根目录的 `PROJECT-CARD.md` + 项目自身文档 | 项目经理 |
| **任务** | 一次派发的工作 | 派工单（**项目根目录** + 目标/输入/输出/验收标准/证据落点） | 派工方（PM 或 Chief） |
| **资源与权限** | 模型、网关、组织权 | 模型分配表 + Main Bot 权限 | Chief |

## 二、八条原则（每条都可检查）

1. **岗位不绑项目。** 岗位卡零项目事实（路径、阶段、测试数）；项目事实写在项目档案卡里。
2. **项目事实只进文件。** 因为插件作者为提示词缓存刻意让身份段"只依赖 Bot 自己的记录"；项目事实进 instructions 既会腐烂，又会让前缀缓存整体失效。
3. **身份段字节稳定。** 改 `instructions` 视为一次有代价的操作，必须说明影响。
4. **一文件一主。** 写权以项目档案卡白名单为准，同文件禁止并发写。
5. **只追加、不覆盖；共享文本先读后写。** 群公告、团队文档禁止凭记忆整段重写。
6. **结论必须带证据强度**（文档调研 / 源码检查 / 模拟边界 / 真实组件 / 真实外部服务 / 端到端验收）；性能数字要么复测过、要么标注"单次观测"。
7. **一次性的活不建编制。** 只在"重复 ≥3 次 / 需独立记忆 / 需独立写权"三条中至少满足一条时，才建常驻 Bot；否则走临时工（subagent）或复用现有岗位。
8. **权限红线不松。** 人工审批是唯一闸门；研究角色、聊天入口、模型网关都没有模拟执行权限；建人/改名/换模型只有 Main Bot 能做。

## 三、依据

**来自插件作者（`ds-bot` v0.1.4 源码）**

- 团队状态里只有 Bots / Rooms / Exchanges / Memory(bot+team) / 权限，**没有 project 对象**（`store.js:14`）；
- Bot 记录里只有 name / role / instructions / model 等，**没有项目字段**（`roster.js:69-82`）；
- 全团队**共用一个 workspace**（`roster.js:14-22`）；
- 项目知识被降级为**记忆 topic**，且"项目文件不是记忆、每个 Session 重读"（`memory.js:775/303`）；
- 身份段为缓存保持字节稳定（`prompt.js:1-2`）。

**来自我们踩过的坑**

- 给 Chief 切到没配 key 的官网路由 → 立下"换模型先验凭据"；
- 把 `<项目根>` 写进岗位卡 → 立下"岗位零项目事实"；
- 凭记忆重写群公告，疑似覆盖了群内写入的规则 → 立下"共享文本先读后写"。

## 四、现状（2026-10-13 体检后）

- **8 个成员**：Chief（Main Bot/管理员）+ 项目经理、项目助理、数据工程师、研究链工程师、模拟执行工程师、质量与测试、调研官。
- **岗位卡合规**：7 个自定义岗位项目事实泄漏 0 处、五段结构齐全。
- **模型**：全部在网关并发限额内，无人使用未配凭据的路由。
- **记忆**：team `MEMORY.md` 只放团队级事实；项目事实在 topic `<项目名>` / `bot-mgmt`。
- **文档**：设计意图（01）、创建规范（02）、岗位规范（03）、体检报告（04）、本理念（05）。
- **项目注册表**：`..\projects.md`。

## 五、边界与未解决（诚实版）

1. **项目层是约定，不是插件的强制机制。** 插件不会阻止任何人把项目路径写进岗位卡——靠的是派工单里那句"项目根目录"和这里的纪律。
2. **团队记忆可能回潮。** 记忆评审是自动写的，仍可能把项目事实放进 `MEMORY.md`；发现就迁 topic。
3. **探活只能探路由。** Bot 是 Session 不是进程，没有心跳语义；本阶段决定不建探活机制。
4. **跨项目复用要靠"派工携带项目"这句话落地**，没有原生的项目切换器。
5. **改 `instructions` 有缓存成本**，所以岗位卡要少改、改前想清楚。
